Over time I’ve been slowly improving the workflow I use to generate AI illustrations for these newsletters.

In the past I would craft my own prompts for [the Bing image generator](https://www.bing.com/images/create?FORM=IRPGEN) or [the AI image generator built into Substack](https://support.substack.com/hc/en-us/articles/4697212547860-How-do-I-add-free-images-or-pictures-to-my-Substack-post). But I found that I wasn’t especially good at coming up with good prompts reliably.

I’ve found that Claude is much better than I am at prompt engineering. So for a while I would copy my articles into Claude and ask it to suggest image prompts for the article at several levels of abstractness. I’d then copy the prompts back into Substack’s image generator and see which results I liked best. This worked better, but was quite tedious to do for each article.

Currently I use [a local shell script](https://github.com/narthur/dotfiles/blob/main/bin/generate-illustrations) to both generate the prompts and then generate illustrations from these prompts for me to choose from.

1. I run the script in my terminal.
2. The script asks me for the text of my article. I paste the whole article, and add “END” on the next line to signal the script to proceed.
3. The script sends a request to Claude Haiku 3 to [extract key themes and concepts](https://github.com/narthur/dotfiles/blob/main/bin/generate-illustrations#L17-L40) from the article.
4. The script loops through [a list of styles](https://github.com/narthur/dotfiles/blob/main/bin/generate-illustrations#L6-L15), asking Claude Haiku 3 to [produce an image prompt](https://github.com/narthur/dotfiles/blob/main/bin/generate-illustrations#L42-L95) for each style given the themes and concepts extracted in step three. It makes two such requests for each style.
5. The script pauses to allow me to review and approve the generated prompts.
6. Once approved, the script proceeds to generate an image for each prompt using [Z-Image-Turbo running on my local machine](https://github.com/narthur/z-experiments).
7. I review the resulting images and select one to be used as the article’s illustration.

I’ve found this workflow to reliably and efficiently produce high-quality illustrations for my articles at very low cost. The Haiku 3 requests cost me less than a penny per run, and the actual image generation is ~free since it runs on my local machine.

<figure><img src="/writing/my-ai-illustration-workflow/2.webp" alt="" width="728" height="392.80575539568343" loading="lazy"></figure>

One limitation of this approach is that it requires you have a computer beefy enough to run an image generator locally. I have an NVIDIA GeForce RTX 3060 with 12GB VRAM which makes this practical. But without a dedicated graphics card I’d probably be back to using a hosted image generator, perhaps using [OpenAI’s API](https://platform.openai.com/docs/guides/image-generation). But of course that would mean [higher cost per run](https://openai.com/api/pricing/).
